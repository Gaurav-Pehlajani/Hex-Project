Data flow — step by step

1
User enters domain/IP
React frontend calls extractTarget(), identifies if input is domain or IPv4.
2
Parallel API calls fire
Promise.all() simultaneously queries VirusTotal, Geolocation, WHOIS, Subdomains. Shodan is queried after resolving the IP.
3
Netlify proxy bridges execute
subdomains.js, shodan.js run server-side — API keys never reach the browser, CORS bypassed.
4
Risk score calculated
calculateRiskScore() combines VT malicious flags + Shodan open port data into a 0–100% threat metric.
5
Data injected into AI prompt
All raw data appended as [SYSTEM DATA ATTACHMENT] in the user message to the LLM.
6
LLM streams report
sendToDeepSeek() streams token-by-token to the UI. Fallback logic activates on errors.
7
PDF report generated
jsPDF compiles dashboard + AI summary into HEX-Report-DOMAIN.pdf for export.
Fallback engine — the 3-tier model queue
Tier 1: llama-3.3-70b-versatile (primary — best reasoning)
Tier 2: llama-3.1-70b-versatile (secondary — same capability, different key)
Tier 3: llama-3.1-8b-instant (tertiary — fastest, recovery mode)
HTTP 429 → rotate API key → switch to backup key → switch to 8B instant
HTTP 503 → circuit break → model switch
Timeout → AbortController fires → retry with exponential backoff
Failover latency measured at <400ms in testing.

Key functions

Know what each function does, where it lives, and its purpose.

extractTarget(msg)
deepseek-client.ts ▼
Parses the user's natural language input to extract an IP address or domain name using regex. This is the entry point of every scan — if this fails, nothing runs. It differentiates between an IPv4 pattern and a domain string to decide which APIs to call next.
queryVirusTotal(target)
deepseek-client.ts ▼
Calls the VirusTotal API v3 via the Netlify proxy. Returns malicious count, reputation score, suspicious count, and verdict (CLEAN/SUSPICIOUS/MALICIOUS). This data becomes the primary input for the AI risk scoring system.
queryShodan(resolvedIP)
deepseek-client.ts ▼
Queries Shodan's host endpoint for a resolved IP address (domain → IP first via geolocation). Returns open ports, service banners, known CVEs, and ISP data. The proxy (shodan.js) handles this server-side to protect the API key and bypass CORS.
querySubdomains(target)
deepseek-client.ts ▼
Runs parallel requests to both VirusTotal subdomain endpoint and HackerTarget's DNS lookup. Results are deduplicated using a Set. Combining both sources discovered 15% more subdomains than either tool alone in benchmarks.
queryGeolocation(target)
deepseek-client.ts ▼
Calls ip-api.com to resolve the physical location (city, country, lat/long), ISP, ASN, and hosting provider of the target. Also resolves domain → IP, which is then passed into queryShodan(). Feeds the Leaflet map component.
calculateRiskScore(vt, geo, shodan)
deepseek-client.ts ▼
Takes the formatted strings from VirusTotal, geolocation, and Shodan and computes a 0–100% custom risk metric. Weighs factors like malicious detection count, open dangerous ports (e.g. 3389 RDP, 22 SSH), and known CVEs. This single number drives the dashboard threat bar.
sendToDeepSeek(convo, sysPrompt, ...)
deepseek-client.ts ▼
The core AI function. Takes conversation history + system prompt, calls Groq API, and streams the response token-by-token via the onChunk callback. Contains the full 3-tier fallback logic (Tier 1 → Tier 2 → Tier 3 model with key rotation).
sendMessage()
Index.tsx ▼
The master orchestrator function in the frontend. When a user submits a query it fires all 4 API queries in parallel with Promise.all(), awaits Shodan, calculates risk score, injects all data into the AI prompt and starts the stream.
generatePDFReport()
Index.tsx ▼
Uses jsPDF to programmatically create a formatted PDF. Sets black header with "HEX AI" branding, adds threat assessment bar, compiles tactical infrastructure data and AI summary. Saves as HEX-Report-[TARGET].pdf.
exports.handler() (proxy files)
netlify/functions/ ▼
Each Netlify serverless function is an AWS Lambda handler. They receive the target parameter, read the API key from Netlify environment variables, call the external API, and return normalized JSON. This is critical for hiding API keys and bypassing CORS.

Interview Q&A

Tap to reveal answers for expected questions.

What exactly does Hex AI do — explain it to a non-technical person.BASIC
▼
Hex AI is like a security X-ray for any website. You just type in a domain name, and within 15 seconds the system tells you: where the server is located, what security weaknesses exist, what hidden sub-sites are attached to it, and whether it's been flagged as malicious by antivirus engines. Then an AI writes a simple report explaining the risks in plain English — no technical knowledge needed.
Why serverless? Why not a normal backend server?TECHNICAL
▼
Three reasons. First, real-time — a traditional server caches data on a schedule, so intelligence can be 24 hours stale. Serverless functions fetch live data at the exact moment of the scan. Second, cost — no always-on server means near-zero cost for infrastructure. Third, OPSEC — requests originate from Netlify's distributed edge IPs worldwide, not from the researcher's IP, so the target's IDS cannot trace the scan back to us.
How does the multi-model fallback engine work?TECHNICAL
▼
We maintain 3 API keys and 3 Groq model tiers. On every AI call, the system first tries Llama-3.3-70B with the primary key. If it receives HTTP 429 (rate limit), it automatically rotates to the backup key. If that also fails, it switches to the 8B-instant model for fast recovery. Failover happens in under 400ms, ensuring 24/7 availability.
How do you protect the API keys?TECHNICAL
▼
All API keys are stored as Netlify environment variables — they only exist server-side in the Node.js Lambda runtime. They are never sent to the browser, never appear in client-side JavaScript, and Netlify auto-redacts them from build logs. Input from users is also sanitized with regex before any request leaves the system to prevent SSRF attacks.
Is this ethical? Couldn't this be used for hacking?ETHICS
▼
Hex AI uses only passive OSINT — it queries existing, publicly authorized databases. It does not send unauthorized probe packets to any target server. This is the same methodology used by professional SOC analysts and is entirely legal. We follow a strict ethical charter: no active intrusion, no data manipulation, and we encourage responsible disclosure.
What is OSINT and how does your project use it?BASIC
▼
OSINT stands for Open Source Intelligence — legally collecting information from public sources. Hex AI uses three OSINT sources: Shodan (internet-connected device indexer), VirusTotal (aggregates 70+ antivirus scanners), and HackerTarget (subdomain enumeration). By combining all three and using AI to correlate the findings, we achieve an "Intelligence Loop".
How does the CORS proxy work? Why is it needed?TECHNICAL
▼
Browsers enforce a "Same-Origin Policy" — a webpage from domain A cannot directly call an API at domain B without rules. Shodan and some other APIs don't allow browser-origin calls. Our Netlify Functions run server-side (Node.js), which has no such restriction. The browser calls our Netlify function, the function calls Shodan, and returns the data — acting as a trusted middleman proxy.
What are the limitations of the current system?LIMITATIONS
▼
Three main ones. First, cache latency — Shodan indexes the internet on its own schedule, so infrastructure changes in the last 12 hours may not reflect. Second, API rate limits on free tiers. Third, domain privacy — targets using WHOIS privacy protection return limited data.
What are the future enhancements / scalability plans?FUTURE
▼
Roadmap items: (1) MCP integration — allow the AI agent to dynamically discover and use new security tools. (2) Kubernetes orchestration for scanning entire IP ranges in parallel. (3) Mobile app with push alerts. (4) Self-healing AI agent that not only detects threats but auto-applies firewall rules. (5) Heuristic threat correlator using ML to predict attacker lateral movement paths.
How is your project different from using Shodan/VT directly?BASIC
▼
First, aggregation — Shodan shows "Port 80 is open." Hex AI says "Port 80 open with Apache 2.2.15 (12 CVEs), cross-referenced with 3 malicious subdomains found on VT." Second, natural language interface, not CLI. Third, benchmark showed 40 mins of manual work reduced to 15 seconds, with 15% more subdomains discovered.
What is the MCP (Model Context Protocol) you mention?FUTURE
▼
MCP is an open standard that lets AI agents dynamically discover and use external tools through a standardized server-client protocol — similar to how a browser discovers plugins. This allows stateful reasoning loops where the AI independently decides to run a deeper scan based on what it found — without human intervention.
What tech stack did you use and why those choices?TECHNICAL
▼
React 18 + TypeScript for type-safe, fast state updates during streaming. Vite for build speed. Tailwind + Radix UI for responsive design. Netlify Functions for serverless compute. Supabase for PostgreSQL sessions and history with RLS. GitHub OAuth for seamless auth. Groq for LLM inference due to extremely low latency (LPU architecture).

Presentation Pitch Guide

Word-for-word guide for your demo.

Opening (First 30 seconds)
"Good morning. Our project is called Hex AI — a cyber threat intelligence platform. In the current landscape, a security analyst manually gathering intelligence about a website takes 30 to 40 minutes across multiple disconnected tools. Hex AI does the same thing in 15 seconds, with higher accuracy, powered by AI. Let me show you how."
The Problem (15 seconds)
"The core problem is data fragmentation. Threat intelligence is scattered across Shodan, VirusTotal, DNS records, and WHOIS. Correlating all of this manually creates analyst fatigue and delays. We built a unified platform that aggregates, correlates, and explains this data automatically."
The Architecture (30 seconds)
"The system has three layers. The frontend is a React application — the intelligence desktop. The middle layer is Netlify serverless functions — these act as secure proxy bridges that call Shodan, VirusTotal, and HackerTarget on the server side, so API keys are never exposed. The third layer is our Resilient AI Engine using Groq's Llama 3, which synthesizes all data into plain-English security reports."
The Key Innovation (20 seconds)
"Our most significant technical contribution is the multi-model fallback engine. Most AI-driven tools have a single point of failure — one API key, one model. If it rate-limits, the whole system breaks. We solved this with a 3-tier fallback queue across 3 API keys and 3 model sizes, with automatic failover in under 400 milliseconds. This ensures 24/7 availability."
Results (15 seconds)
"In our benchmark against google.com, we identified 120+ subdomains with 98% accuracy validated against manual dig lookups. Reconnaissance time: 15 seconds versus 40 minutes manually. Our combined multi-source approach found 15% more subdomains than any single tool used alone."
Closing / Future (15 seconds)
"The roadmap includes full MCP integration — allowing the AI to autonomously discover and orchestrate any security tool. We also plan Kubernetes-based scaling for enterprise IP range scanning and a self-healing AI agent that not only detects threats but applies remediation automatically. Thank you."
3 Golden Rules for Demo Day
1. Lead with the problem, not the tech. Don't start with "we used React." Start with "analysts waste 40 minutes." Judges care about value first.
2. Own your numbers. 15 seconds, 98% accuracy, 400ms failover, 15% more subdomains. These are your ammunition — memorize them.
3. If you don't know, be honest and bridge. "That's a great question — we haven't implemented that yet, but in our roadmap it would work by..." — judges respect intellectual honesty.
